# ADR-0013: 推論モデルの思考を本文と分けて扱う

- 状態: 採択
- 日付: 2026-08-29

## 文脈

Ollama 上の `qwen3.5:9b` で会話したところ、生成は完了しているのにチャット
へ何も表示されないという症状が出た。実際のリクエストを投げて応答を確認した
ところ、原因が判明した。

推論モデルは思考と本文を別のフィールドで返す。

| プロバイダ | 思考の場所 |
|---|---|
| OpenAI 互換 (Ollama) | `delta.reasoning` |
| OpenAI 互換 (その他) | `delta.reasoning_content` |
| Anthropic | `content_block_delta` の `thinking_delta` |
| Gemini | `parts[]` の `thought: true` |

`max_tokens` を 256 にして試すと、224 チャンクすべてが思考で本文は 0 文字、
`finish_reason` は `length` だった。一言の返事にも 327 トークンを要し、その
ほとんどが思考である。

## 決定

思考は本文と明確に分けて扱う。

1. `Delta::Reasoning` として本文とは別の種別で流す
2. 会話には保存しない。表情にもリップシンクにも渡さない
3. 進行中であることを示すため、チャットに「考えています」と末尾だけを出す
4. 本文が 1 文字も出ずに終わったら理由を伝える
5. `max_tokens` は任意とし、既定では送らない

## 検討した代替案

**思考を捨てる（当初の実装）。** 採用しない。思考が本文に混ざらないという
点では正しいが、何も表示されないため利用者には不具合と区別がつかない。実際
にそう報告された。

**思考を本文として表示する。** 採用しない。キャラクターが内心を垂れ流す
ことになり、体験を壊す。感情タグの解析やリップシンクにも思考が流れ込む。

**`max_tokens` に大きな既定値を置く。** 採用しない。適切な値はモデルに
よって桁が違う。必須なのは Anthropic だけなので、送らないほうが正しい。

## 影響

- 思考の長いモデルでは最初の応答までかなり待つ。待たされていることが
  分かる表示が不可欠になる
- `max_tokens` が任意になったため、保存形は `Option<u32>` になった。既存の
  記録は数値のまま読めるので移行は不要
- 感情プロトコルの説明も思考の対象になる。思考を短くしたい場合は
  `emotionMode` を切る選択肢がある
