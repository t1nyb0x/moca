# ADR-0010: 会話履歴は JSON ファイルで永続化する

- 状態: 採択
- 日付: 2026-08-29
- 関連: 未決事項 U-3 の解決

## 文脈

会話履歴、キャラクタープロファイル、プロバイダプロファイルを永続化する必要がある（要件 F-09、F-10）。想定利用者は個人であり、会話数は数百から数千のオーダーに留まる見込みである。

## 決定

- 設定とプロファイル: `tauri-plugin-store` による JSON（アプリ設定ディレクトリ）
- 会話履歴: 会話 1 件につき JSON ファイル 1 つ。加えて一覧表示用のインデックスファイルを 1 つ持つ

```
{app_data_dir}/
├─ settings.json
├─ characters/{characterId}.json
├─ providers.json
└─ conversations/
   ├─ index.json                 # id, characterId, title, updatedAt のみ
   └─ {conversationId}.json      # 本体
```

インデックスを分けるのは、会話一覧を開くたびに全会話を読まないためである。

## 検討した代替案

**SQLite (`rusqlite` / `tauri-plugin-sql`)。** 現時点では採用しない。全文検索や大量データの部分読み出しが必要になれば優位だが、MVP の要件にはない。`rusqlite` の `bundled` 機能は C コードのコンパイルを伴い、Windows ビルドの構成要素が 1 つ増える。

移行の判断基準を明示しておく。**次のいずれかに該当した時点で SQLite への移行を再検討する。**

- 会話件数が 1,000 件を超え、一覧表示に体感できる遅延が出た
- 会話横断の全文検索が要件化された
- 長期記憶 / RAG（P4）でベクトル検索が必要になった

**1 ファイルに全会話をまとめる。** 採用しない。1 メッセージ追記のたびに全体を書き戻すことになり、会話が伸びるほど書き込み量が増える。破損時の被害範囲も全会話に及ぶ。

## 影響

- 書き込みは一時ファイルへ書いてから `rename` する atomic write とする。ストリーミング中のクラッシュで会話ファイルを壊さない
- ストリーミング中は毎トークン保存せず、応答完了時および中断時に保存する
- スキーマにバージョン番号 (`schemaVersion`) を持たせ、将来の移行に備える
- 会話本体には感情タグを含む原文 (`rawContent`) と解析済みの感情列を保存する。再開時に表情推移を再現するため（要件 8.3）
