# ADR-0002: LLM 通信を Rust コアに置く

- 状態: 採択
- 日付: 2026-08-29

## 文脈

LLM プロバイダへの HTTP 通信は、WebView 側の `fetch` からでも Rust 側の `reqwest` からでも実装できる。本アプリは OpenAI 互換 / Anthropic / Gemini の 3 系統に対応し、いずれも API キーを伴う（ローカル LLM を除く）。

## 決定

LLM への通信はすべて Rust コアで行う。WebView 側は Tauri コマンドを呼ぶだけとし、HTTP を直接叩かない。

## 検討した代替案

**WebView 側から fetch する。** 採用しない。理由は 3 点。

1. API キーをレンダラプロセスへ渡す必要が生じる。WebView は表示するコンテンツの性質上、Rust プロセスより攻撃面が広い。要件 F-11-3 に反する
2. 外部 API へのクロスオリジン要求が CORS の制約を受ける。Anthropic API はブラウザからの直接呼び出しを想定しておらず、回避には専用ヘッダの付与が必要になる
3. プロバイダごとの差異（システムプロンプトの配置、ロール名、SSE の構造）を吸収する層が、テストしにくい WebView 側に置かれる

## 影響

- API キーは Rust プロセス内に留まり、IPC 境界を越えない
- 3 プロバイダの差異が `llm/` モジュールに閉じる。プロバイダ追加は 1 ファイルの追加で済む
- SSE のフレーム分解を Rust で実装する必要がある。`sse.rs` として共通化し、アダプタごとに重複させない
- ストリーミング応答を IPC でフロントへ運ぶ機構が必要になる。これは ADR-0009 で扱う
- Anthropic は Rust 公式 SDK を提供していないため、`reqwest` による raw HTTP で実装する
