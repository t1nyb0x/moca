# ADR-0015: PMX の読み込みに第三者ライブラリを用いる

- 状態: 採択
- 日付: 2026-08-29
- 関連: [ADR-0004](0004-vrm-first-pmx-behind-adapter.md)、要件 R-1

## 文脈

ADR-0004 では PMX 対応にあたり three.js の `MMDLoader` を使う前提で計画して
いた。要件 R-1 には「`examples/jsm` 配下であり API 安定性の保証がない」と
記録していた。

0.3 の着手時に調べたところ、**MMD 関連モジュールは three.js から削除されて
いた**。r171 で非推奨 (#29698)、r172 で削除 (#30003) されている。理由は
公式に説明されている。

> MMD に詳しい貢献者が誰もいない。巨大で複雑なコード、専用トゥーン
> マテリアル、別途パーサが必要という事情から、第三者リポジトリへ移すべき

移管先として案内された `takahirox/three-mmd-loader` は、README に
「Coming soon...」とあるだけで中身が無い（2024-12 以降動きなし）。

つまり公式の後継は存在しない。

## 決定

`@yohawing/three-mmd-loader` を用いる。

選定時に確認したこと:

- MIT ライセンス
- three `>=0.176.0 <1.0.0` に対応（当方は 0.185.1）
- TypeScript 優先の ESM。当プロジェクトの厳格な型設定と相性がよい
- PMX / PMD / VMD / VPD の解析に対応
- **`mesh.morphTargetDictionary` に MMD のモーフ名を入れる。** three.js
  標準の経路なので、既存の感情マッピングがそのまま乗る。ここが取れなければ
  設計をやり直すところだった

## 検討した代替案

**削除されたモジュールを移植する。** 採用しない。`MMDLoader` 52KB、
`MMDAnimationHelper` 25KB、`MMDPhysics` 28KB の計 106KB を、内容を理解しない
まま抱えることになる。r171 から r185 への API 差分の吸収も要る。three.js
の更新のたびに負債が効いてくる。

**`@moeru/three-mmd`。** 有力な代替。物理演算が別パッケージで、SpringBone
版を選べば ammo.js の重い WASM を避けられる利点がある。ただし版が 0.1.2 と
早い段階であり、今回は見送った。

**PMX を諦める。** 採用しない。当初からの要件であり、判断は利用者に属する。

## 影響

- **CSP に `wasm-unsafe-eval` が要る。** このローダーは WebAssembly を使う。
  `script-src 'self'` だけでは `WebAssembly.compile` が塞がれ、何のエラーも
  出さずに失敗する。テクスチャで同種の失敗をしているため先に手当てした
- **PMX はテクスチャを外部ファイルとして参照する。** VRM のように 1 ファイル
  で完結しないため、アセットプロトコルの許可をモデルのあるディレクトリまで
  広げる必要がある。上位へは広げない
- 依存先は版が 0.8.2 と若い。`ModelAdapter` の境界を保ち、差し替えられる
  状態を維持する
- 揺れ物はランタイムの `stateful-spring` を使う。Bullet の WASM を積まずに
  済むため軽い。外部バックエンド（Bullet）も選べるが、髪とスカートが揺れれば
  十分と判断した
- **適用の順序に注意が要る。** ランタイムの `tick` はボーンとモーフを書き
  換えるため、表情と呼吸を先に当てると毎フレーム消される。値を持ち回り、
  `tick` の直後に書き込む
- 物理演算が失敗しても描画は続ける。揺れないだけなら見た目が固いで済むが、
  描画ごと止めると何も見えなくなる
- 視線追従は未対応。PMX に LookAt の仕組みが無く、目のボーンを直接動かす
  必要がある
