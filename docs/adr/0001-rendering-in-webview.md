# ADR-0001: 3D 描画を WebView 側 (three.js) に置く

- 状態: 採択
- 日付: 2026-08-29

## 文脈

Tauri アプリで VRM / PMX を描画する方法は大きく 2 つある。Rust 側でネイティブに描画する（bevy / wgpu / rend3）か、WebView 内で WebGL を用いる（three.js）か。

VRM は表情 (Expression)、視線 (LookAt)、揺れ物 (SpringBone)、人型ボーンの正規化といった仕様固有の機能を持つ。PMX はさらにモーフと剛体・ジョイントの物理演算を持つ。これらは単なるメッシュ描画ではなく、形式ごとの仕様実装である。

## 決定

3D 描画は WebView2 内で `three.js` + `@pixiv/three-vrm` により行う。

## 検討した代替案

**Rust ネイティブ描画 (bevy / wgpu)。** 採用しない。Rust の VRM ローダーは実装が限定的で、SpringBone や Expression の解決を自前で実装する必要が生じる。PMX に至っては物理演算を含めて実質フルスクラッチとなる。本プロジェクトの価値は感情表現の設計にあり、ファイル形式の再実装に工数を割く合理性がない。

**Unity / Godot を別プロセスで動かす。** 採用しない。配布サイズと起動時間が跳ね上がり、プロセス間同期の複雑さが感情表現の応答性を損なう。

## 影響

- `@pixiv/three-vrm` が VRM 0.x を 1.0 相当の API へ正規化するため、要件 F-01-3（0.x と 1.0 の両対応）が実質的に無償で満たされる
- WebGL 性能が GPU ドライバに依存する。ソフトウェアレンダリングにフォールバックした場合は実用に耐えないため、起動時の検出と警告が必要（要件 R-3）
- PMX 対応時は `MMDLoader` を用いるが、これは three.js の `examples/jsm` 配下であり API 安定性の保証がない（要件 R-1）。three.js のバージョンを固定する
- 描画コードは単体テストが困難となる。この影響への対処は ADR-0005 で扱う
