# ADR-0005: モーション制御を純粋関数化し、副作用を MorphApplier に隔離する

- 状態: 採択
- 日付: 2026-08-29

## 文脈

CLAUDE.md はテスト駆動開発とカバレッジ 80% 以上を求めている。一方 ADR-0001 により描画は three.js で行われ、three.js のオブジェクトを直接操作するコードは単体テストが極めて困難である（WebGL コンテキスト、シーングラフ、フレームループへの依存）。

まばたき、サッケード、呼吸、表情遷移、リップシンクといった挙動は、素朴に書くと「毎フレーム VRM オブジェクトのプロパティを書き換える関数」になり、そのままではテストできない。

## 決定

すべてのモーション制御を、次の形の純粋関数として実装する。

```ts
evaluate(state: S, elapsedSeconds: number): WeightMap   // 副作用なし
advance(state: S, deltaSeconds: number): S              // 次状態を返す
```

three.js への書き込みは `MorphApplier` 1 クラスに限定する。コントローラは three.js を import しない。

乱数を用いるコントローラ（まばたき、サッケード）は、**乱数生成器の状態を `state` に含めて決定的にする**。

## 検討した代替案

**コントローラが直接 VRM を書き換える。** 採用しない。テストのために WebGL のモックが必要になり、実質的にテストを書かなくなる。カバレッジ目標が達成できない。

**`Math.random()` をそのまま使い、乱数部分はテストしない。** 採用しない。まばたき間隔の分布や、サッケードが可動域を超えないことは検証したい性質である。seed を state に持てば通常の単体テストで検証できる。

## 影響

- `domain/` は three.js にも Tauri にも依存しない。依存の向きが常に内側を向く
- テスト不能な領域が `render/` の `MorphApplier` と `Viewer` に限定される。カバレッジ 80% はロジック層に課し、この層は対象から除外する
- 複数コントローラの出力を合成する責務が `MorphApplier` に集まる。合成規則（キーごとの最大値採用、口モーフのリップシンク優先、合計重みの正規化）を 1 箇所で管理できる
- コントローラの状態を外部から与えられるため、会話再開時に過去の感情状態を復元することが容易になる（要件 F-02-4）
