# ADR-0017: moca は VRM と PMX に留まり、Unity 資産を扱わない

- 状態: 採択
- 日付: 2026-08-30
- 関連: [ADR-0004](0004-vrm-first-pmx-behind-adapter.md)、[ADR-0015](0015-pmx-via-third-party-loader.md)、要件 F-14

## 文脈

0.7 で感情に応じた姿勢を入れた後、「待機中に座らせられないか」「Unity の
`.unitypackage` で配られているモデルを読めないか」という話が続けて出た。

どちらも試したうえで、同じ場所へ着地した。**規格に乗ったものは素直に動き、
乗っていないものは急に苦しくなる。**

### 座り姿を試した結果

手続きでボーンを回して女の子座りと横座りを作り、4 度作り変えた。届かなかった。

- 膝を 135 度以上折るとふくらはぎが太ももへ融合する。肌の追従の限界であり、
  どの角度を選んでも避けられない
- スカートは腰から垂れる紐の束であり、太ももの上に乗る計算ではない。床に
  座れば太ももは必ず水平になるので、垂れた円錐の外へ出る

VRM の揺れ物は「垂れて、球に当たって押しのけられる」だけである。布として
掛ける仕組みではない。

### `.unitypackage` の中身を読んだ結果

実物（Tokyo6 の配布物）を展開して確かめた。

| 中身 | moca から見た状態 |
|---|---|
| `FBX` と取り込み設定 | 骨とモーフは読める。人型ボーンの対応も `.meta` にある |
| `.anim` 18 本 | すべて表情のモーフ。ボーンのカーブは空 |
| `.mat` 8 枚 | Unity のシェーダ前提。移植が要る |
| `prefab` | **Magica Cloth**。第三者の実行時資産で、独自形式の保存データ |

`.anim` は VRM の表情そのものなので移せる。しかし材質は書き直し、布は解法
ごと作り直しになる。次のモデルが別のシェーダや別の布資産を使っていれば、
また一から。

**Unity は組み込めない。** ライブラリとして他のアプリへ埋め込む形では配られて
おらず、WebGL の書き出しは独立したアプリであって部品ではない。これは技術選定の
問題ではなく、どの構成でも成り立たない。

## 決定

**moca は VRM と PMX に留まる。** Unity 資産は直接扱わない。変換が要るものは、
Unity の editor 拡張など**アプリの外**で VRM へ落としてから読む。

**マスコットとしての自然な振る舞い（布が正しく振る舞い、座ったり動いたりする）
は、moca の目標に含めない。** それを目指すなら Unity で作るのが素直であり、
別の製品として立てる。

moca の芯は「LLM の返答に応じて表情と体が動く対話」である。ここは規格に乗った
モデルなら素直に働く。規格から外れるほどモデルごとの手当てに時間が溶け、芯が
痩せる。ADR-0015 で PMX について下した判断と同じ理由による。

## 検討した代替案

**moca が `.unitypackage` を読む。** 採用しない。読むこと自体はできるが、読んだ
後に Unity の実行時の振る舞いを再現しないと絵にならない。材質はシェーダごとの
移植、布は解法の作り直し。モデルごとに際限がない。ADR-0015 で PMX について
「ほぼ全項目でモデル固有の手当てが要る」と結論した状況が、さらに一段深い形で
再現される。

**moca を Unity で作り直す。** 採用しない。描画以外——LLM 3 系統、感情タグの
解析、会話の保存、資格情報の保管、音声合成の連携、透過ウィンドウとクリック
スルー、トレイ常駐——のすべてを作り直すことになる。試験の数で言えば大半が
描画の外にある。

**核を共有し、描画だけ差し替える。** 採用しない。Rust の核を常駐させて Unity 側
から呼ぶ構成は成り立つが、IPC の契約をもう一組維持することになる。二つの製品を
同時に育てる体力が要る。

## 影響

- 座り姿と身振り（F-15、Issue #22）は、手続きでは届かない。扱うならクリップを
  読む形になる。逆運動学を入れても膝の潰れとスカートの貫通は解けない
- モデルが持っているものが全てである。揺れ物の骨と当たり判定が入っていない
  モデルでは、髪もスカートも動かない。利用者が判断できるよう、診断へ出す
  （Issue #24）
- Unity 資産を使いたい利用者には、UniVRM で VRM へ書き出す道を案内する
