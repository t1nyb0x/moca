# ADR-0016: マスコット表示は単一の透過ウィンドウで実現する

- 状態: 採択
- 日付: 2026-08-30
- 関連: [ADR-0007](0007-react-with-canvas-outside.md)、[ADR-0008](0008-zustand-for-state.md)、要件 F-13

## 文脈

0.6 で要件 P3（デスクトップマスコット）に着手する。透過・枠なし・常時最前面
のウィンドウでモデルだけを机の上に置き、背後のウィンドウはクリックスルーで
操作できる状態を目指す。

素直に思いつく作りは 2 つある。通常のウィンドウとは別にマスコット専用の
ウィンドウを立てるか、1 つのウィンドウの見た目を切り替えるか。

着手前に Tauri 2.11.5 の API を確認し、実機で実証したところ、方式の選択を
決定づける制約が 2 つ見つかった。

**透過は生成時にしか決められない。** `set_decorations`、`set_shadow`、
`set_always_on_top`、`set_ignore_cursor_events` はいずれも実行時に呼べるが、
**`set_transparent` は存在しない**。透過はウィンドウ生成時のフラグである。

**ウィンドウを分けるとストアが割れる。** Tauri のウィンドウは WebView ごと
分かれる。JavaScript の文脈が別になるため、Zustand のストア（ADR-0008）も
2 つになる。表情・リップシンク・会話・読み込み済みモデルの同期に、すべて
IPC を通すことになる。

## 決定

**ウィンドウは 1 つとし、常に透過で生成する。** 通常表示では `body` を
不透明に塗ってふさぎ、マスコット表示ではその塗りを外す。実行時に切り替える
のは、実行時に切り替えられるものだけとする。

| 項目 | 通常表示 | マスコット表示 | 手段 |
|---|---|---|---|
| 透過 | 生成時に有効 | 生成時に有効 | `transparent: true`（固定） |
| 背景 | 不透明 | 透明 | CSS |
| 枠 | あり | なし | `set_decorations` |
| 影 | あり | なし | `set_shadow` |
| 最前面 | しない | する | `set_always_on_top` |
| 大きさ | 利用者の指定 | モデルの外接矩形 | `set_size` |
| クリックスルー | しない | 透明部分のみ | `set_ignore_cursor_events` |

### 実証で確かめたこと (2026-08-29)

方式が成立するかは見た目に依るため、実装前に実物で確認した。

- WebView2 の透過は効く。マスコット表示の背後にあるウィンドウの文字が透けて
  読める
- VRM はアルファ合成されて机の上に載る。髪の輪郭も破綻しない
- `transparent: true` で生成しても、通常表示の見た目は従来どおり変わらない
- `set_decorations(false)` が効き、`WS_CAPTION` が落ちることを確認した

タスクトレイ常駐（F-13-7）も併せて確かめた。`tauri` の features へ
`tray-icon` を足すだけで `TrayIconBuilder` と `Menu` が使え、アイコンが通知
領域に出ることを実機で確認した。追加の依存はこの一語で足りる。

**塗りを外す対象は `body` だけではない。** `.viewer` が
`background: var(--surface-sunken)` を持っているため、`body` を透明にしても
モデルの後ろだけ不透明な板が残った。透過にすべき要素を数え漏らすとこの形で
現れる。

### クリックスルーの当たり判定

`set_ignore_cursor_events(true)` にすると、**WebView へマウスの動きが一切
届かなくなる**。画面側では「モデルの上に戻ってきた」ことを検知できず、
一度スルーにすると二度と掴めない。

したがって判定は Rust 側で行う。`cursor_position()` を定期的に読み、その点が
モデルの上かどうかで `ignore` を切り替える。判定にはキャンバスのアルファ値を
用いる。腕と胴の隙間や髪の外側まで見たとおりに抜けるためである。

## 検討した代替案

**マスコット専用のウィンドウを別に立てる。** 採用しない。見た目の分離は最も
きれいだが、ストアが割れる代償が大きい。表情もリップシンクも会話も、いま
1 つのストアの上で組み立てられている（ADR-0007、ADR-0008）。これを IPC 越しの
同期に置き換えるのは、マスコット表示のために設計の中心を作り替えることに
なる。

**モードを切り替えるたびにウィンドウを作り直す。** 採用しない。透過を生成時
にしか決められない制約は回避できるが、WebView ごと作り直すためページが再読み
込みされる。会話の途中経過が失われ、20〜60MB の VRM を読み直すことになる。
切り替えのたびに数秒待たされる。

**クリックスルーを矩形単位にする。** 採用しない。モデルは矩形ではない。腕と
胴の隙間や髪の外側が掴めてしまい、「モデルだけが机の上にいる」感覚が壊れる。
要件 F-13-5 を満たさない。

## 影響

- 通常表示のウィンドウも透過フラグを持つ。背景を CSS で塗り忘れた要素は
  そのまま透けるため、新しい画面を足すときは背景の指定に注意する
- 透過ウィンドウでは OS 側の丸角や影の扱いが通常のウィンドウと異なる。
  通常表示では `set_shadow(true)` で補う
- クリックスルーの判定にカーソル位置のポーリングが要る。間隔と負荷は実装時に
  実測して定める
